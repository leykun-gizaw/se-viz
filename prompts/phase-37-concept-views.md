# Phase 37: Algorithms and statistics concept views

## Why this phase exists
Some DS 210 ideas are not "watch memory change": Big O growth (Week 1), search and sort (Week 1),
sampling distributions and hypothesis testing (Week 5). SE-Viz already has non-memory concept views
(Phase 11: pipeline, before-after, dual-trace). This phase adds three more in the same player, with
the same step controls and explanation panel.

## Context to read
- `src/engine/trace/types.ts` (`TraceView`, concept payloads), `src/components/concept/*`,
  `prompts/phase-11-concept-view-model.md` and its report, `beats.ts` (`supportsBeats`).
- The Studio shell and explanation panel (Phase 28), derived explanations (Phase 32).

## Hard constraints
- Frontend only, TS strict; all gates pass including the bundle check. **No new dependencies**; draw
  with SVG and React, using the `--se-*` tokens.
- Additive trace changes only: new `TraceView` kinds and payloads, documented in
  `docs/TRACE_FORMAT.md`. Existing views unchanged.
- Traces are generated by deterministic TypeScript generators (seeded random numbers), not
  recorded from Pyodide, so they load instantly.
- Both themes; reduced motion respected; colors that must be told apart also differ in lightness.

## What to build
1. **`bars` view (search and sort):** an array as bars with values, per step: compared indices,
   swapped indices, the sorted region, a pointer or range for search (low, mid, high). Generators
   for linear search, binary search, bubble sort, insertion sort, selection sort, merge sort
   (show the split and merge levels), each with comparison and swap counters.
2. **`growth` view (Big O):** curves for O(1), O(log n), O(n), O(n log n), O(n^2) on shared axes;
   each step increases n and shows the operation counts as a table and as moving markers, with a
   caption comparing two curves at the current n.
3. **`distribution` view (statistics):** a histogram that builds as samples are drawn; mode
   "sampling distribution" (draw many sample means from a skewed population and watch the shape
   become normal), and mode "hypothesis test" (null distribution, the observed statistic marker,
   the shaded tail area and the p-value, one or two tailed).
4. **Explanations:** authored `explain` text for every generated step, written by the generator
   from its own state (e.g. "Compared 7 and 3. 7 is bigger, so they swap. Swaps so far: 4.").
5. **Modules:** register each generated trace through top-level `src/content/fixtures/*.ts` files
   (the catalog only discovers that level) for now; the DS 210 content phase will place them in the
   course.

## Tests
- Generators: deterministic output for a seed; sort results are sorted; counters correct;
  binary search finds present and absent targets.
- Rendering snapshots per view and mode.
- Validation of the new payloads.

## Acceptance criteria
1. Gates pass; no new dependency; additive and documented.
2. Every generator's explanation text matches its state at every step (golden tests).
3. The sampling distribution visibly approaches a bell shape; the hypothesis test's p-value matches
   a direct calculation within rounding.
4. Both themes and presentation mode look right (screenshots in the report).
